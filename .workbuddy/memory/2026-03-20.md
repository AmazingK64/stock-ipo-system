### 12. 修复实时孖展数据显示已截止股票问题
**问题**: 实时孖展数据中出现了已截止申购的股票,应该只显示申购中的股票。

**分析**: 后端 `/api/margin-data` 接口的过滤逻辑不够完善:
- 原逻辑只检查静态数据中的 `subscribeIPOs` 列表
- 没有根据申购截止日期进行实时判断

**解决方案**: 改进 `/api/margin-data` 接口的过滤逻辑:
1. 获取当前时间和日期
2. 检查股票是否在静态数据的申购中列表
3. 检查申购截止日期是否已过(根据当前时间实时判断)
4. 同时满足两个条件才保留孖展数据
5. 添加详细的日志输出,记录被过滤的股票及原因

**关键代码**:
```javascript
// 过滤孖展数据:只保留申购中的股票
const filteredMarginData = marginData.filter(margin => {
  const stockCode = margin.stockCode;
  
  // 1. 检查是否在静态数据的申购中列表
  if (!subscribeStockCodes.has(stockCode)) {
    return false;
  }
  
  // 2. 检查申购截止日期是否已过
  const subscriptionEndDate = subscriptionEndDates.get(stockCode);
  if (subscriptionEndDate) {
    const endDate = new Date(subscriptionEndDate);
    if (endDate < now) {
      return false;
    }
  }
  
  return true;
});
```

### 15. 修复融资分配计算负数问题
**问题**: 融资分配策略中出现负数的资金分配和申购总额。

**根本原因**:
- `remainingCapital` 在循环中递减,可能变成负数
- 最后一个股票的 `allocationRatio` 计算时使用了负的 `remainingCapital`
- 导致后续所有计算都出现负数

**解决方案**:
1. 使用 `Math.min()` 确保资金分配不超过剩余资金:
```typescript
const capitalAllocation = Math.min(totalCapital * allocationRatio, remainingCapital);
```

2. 添加剩余资金检查,跳过资金不足的股票:
```typescript
if (capitalAllocation <= 0) {
  return;
}
```

3. 修正最后一个股票的分配逻辑:
```typescript
if (index === highQualityIPOs.length - 1 && remainingCapital > 0) {
  allocationRatio = remainingCapital / totalCapital;
}
```

4. 确保融资倍数不为负:
```typescript
financingMultiplier = Math.max(0, Math.floor(actualMultiplier));
```

2. 添加详细日志记录过滤原因
3. 根据当前时间实时判断申购是否已截止

**需求**: 当招股书本地数据缺少商业模式、估值等评分维度时，自动从网络搜索获取。
